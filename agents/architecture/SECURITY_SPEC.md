# 🔐 Спецификация Безопасности (SECURITY_SPEC.md)

**Проект:** Тихий ум  
**Модель:** Статический сайт (чистые HTML + CSS + JS) без собственного сервера и базы данных.  
Документ описывает реальную модель безопасности проекта и правила для всех агентов.

---

## 1. Управление Секретами и Учетными Данными
- **Принцип:** Zero Hardcoded Secrets — в проекте НЕТ и не должно появиться ключей, токенов и паролей.
- Все внешние API — **keyless** (Wikiquote, Advice Slip, DummyJSON, MyMemory, SoundHelix) и работают прямо из браузера (CORS `*`).
- Если в будущем появится API с ключом: ключ только через переменные окружения на этапе сборки/деплоя; в репозиторий — исключительно `.env.example` с фиктивными значениями; `.env` в `.gitignore`.
- Запрещено добавлять серверные компоненты с секретами без обновления этого документа и отдельного ADR.

## 2. Аутентификация и Авторизация
- **Отсутствует намеренно:** приложение не имеет пользователей, аккаунтов и серверной части — авторизоваться нечем и негде.
- Единственное «хранилище» — `localStorage` браузера пользователя (настройки, статистика, кеш цитат). Никаких персональных данных, ничего не покидает устройство, кроме запросов к перечисленным API.

## 3. Валидация входных данных и Защита от атак
- **XSS (главный вектор для контентных сайтов):**
  - Весь внешний контент (цитаты, советы, переводы) рендерится **только через `textContent`** — запрет `innerHTML` для любых данных из API.
  - Допустимые `innerHTML`-использования — только со статическими внутренними константами (техники) или числами/именами, введёнными самим пользователем локально (пульт команд, свои сценарии). Нарушение этого правила = баг.
  - Wiki-разметка вычищается в `clean()` (app.js): шаблоны, ссылки, HTML-теги, сущности.
- **Прочее:** SQL/CSRF/RCE неприменимы (нет сервера, нет cookie-сессий, нет мутаций). CORS-политика задаётся внешними API (все отдают `*`).
- **CSP:** для GitHub Pages нельзя задать заголовки; `<meta http-equiv="Content-Security-Policy">` допустим как опциональное ужесточение (connect-src только на домены из config.js) — при добавлении проверить, что не сломал SoundHelix (media) и Google Fonts.

## 4. Service Worker и кеш
- SW кеширует только оболочку приложения (same-origin) и Google Fonts; внешние API проходят напрямую.
- Любое изменение index/app/style/config требует синхронного бампа `?v=N` (index.html) и `CACHE_VERSION` (sw.js) — иначе пользователи получат устаревшую смесь из кеша.
- Кеш навигации хранится под фактическим URL запроса (v49) — чужая страница не может подменить офлайн-оболочку.

## 5. Приватность пользователя
- Аналитики и трекеров нет; телеметрии нет.
- `localStorage`-ключи проекта: `zen*` (настройки, статистика, кеши) — очищаются браузером стандартными средствами; экспорта/синхронизации нет.

## 6. Регламент для агентов
1. Новый внешний источник данных → добавить URL только в `config.js`, проверить CORS и keyless-статус, рендер строго через `textContent`.
2. Любой новый `innerHTML` / `insertAdjacentHTML` — согласовать в плане (Plan-First) и обосновать в ADR.
3. Новые зависимости (скрипты, шрифты, CDN) — запрещены без ADR: проект держится zero-dependency.
