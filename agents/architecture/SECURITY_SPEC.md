# 🔐 Спецификация Безопасности (SECURITY_SPEC.md)

**Проект:** Тихий ум  
Документ определяет требования, регламенты и механизмы информационной безопасности.

---

## 1. Управление Секретами и Учетными Данными
- **Принцип:** Никаких секретов в кодовой базе (Zero Hardcoded Secrets).
- Все чувствительные данные (токены, ключи API, пароли, приватные ключи) передаются исключительно через переменные окружения.
- В репозиторий включается только `.env.example` с фиктивными значениями.
- Файл `.env` должен быть обязательно добавлен в `.gitignore`.

---

## 2. Аутентификация и Авторизация (Auth & Permissions)
- **Механизм аутентификации:** [JWT / Сессионные Cookie / API Key / OAuth 2.0]
- **Хранение паролей:** Использование криптографически стойких алгоритмов хэширования с солью (`bcrypt` / `argon2`).
- **Контроль доступа:** Role-Based Access Control (RBAC) или Attribute-Based (ABAC). Принцип наименьших привилегий (Principle of Least Privilege).

---

## 3. Валидация входных данных и Защита от атак
- **Strict Validation:** Все входящие данные из внешних источников (тело запроса, query параметры, заголовки) проходят обязательную схематическую валидацию (Pydantic / Zod).
- **SQL Injection Prevention:** Использование параметризованных запросов или ORM. Строгий запрет конкатенации сырых SQL-строк.
- **XSS Prevention:** Экранирование HTML-вывода, использование CSP (Content Security Policy) заголовков.
- **CSRF Protection:** Использование SameSite cookie атрибутов или CSRF-токенов для мутирующих запросов.
- **CORS Policy:** Ограничение разрешенных origins только доверенными доменами на production.

---

## 4. Ограничение частоты запросов (Rate Limiting)
- Защита публичных эндпоинтов от перебора (Brute-force) и DoS-атак с помощью лимитеров запросов (например, 100 запросов в минуту на IP).
