# 🏛️ Архитектурные Решения (Architecture Decision Records — ADR)

Каталог предназначен для фиксации фундаментальных технических решений, принятых в проекте.

---

## 🎯 Зачем вести ADR?
Когда над проектом работают разные AI-агенты (или разные сессии), легко забыть, *почему* была выбрана именно такая библиотека, структура данных или протокол взаимодействия. Без ADR новый агент может попытаться «переписать всё на другой стек», сломав обратную совместимость.

---

## 📝 Как создать новый ADR:
1. Скопируй бланк из [`agents/templates/template_adr.md`](file:///agents/templates/template_adr.md).
2. Назови файл по стандарту: `ADR_XXX_<short_name>.md` (например, `ADR_001_database_selection.md`).
3. Заполни разделы:
   - **Контекст:** Какая стояла проблема.
   - **Альтернативы:** Какие варианты сравнивались.
   - **Решение:** Что выбрано и почему.
   - **Последствия:** Плюсы, компромиссы и риски.
4. Ознакомься с эталонным примером в [`ADR_000_example.md`](file:///agents/decisions/ADR_000_example.md).
