# 🏛️ ADR-000: Выбор архитектурного паттерна и стека проекта (Эталонный пример)

- **ID решения:** ADR-000
- **Название:** Выбор модульного монолита на FastAPI + SQLite для MVP
- **Статус:** 🟢 ACCEPTED
- **Дата принятия:** 2026-09-18
- **Авторы/Агенты:** Lead Architect Agent (Gemini 3.8 Flash)

---

## 1. Контекст и проблема
Для реализации проекта требовалось определить базовую архитектуру и стек технологий. Ключевые требования:
- Максимальная скорость разработки первого рабочего MVP.
- Минимальное потребление ресурсов (возможность запуска на VPS с 1 ГБ RAM или локально без Docker-оркестрации).
- Высокая производительность и встроенная асинхронность для обработки очередей и вебхуков.
- Строгая статическая типизация для предотвращения ошибок рантайма.

---

## 2. Рассмотренные альтернативы

### Вариант 1: Микросервисная архитектура (Go / Node.js + PostgreSQL + Redis + RabbitMQ)
- **Плюсы:** Идеальная изоляция сервисов, легкое горизонтальное масштабирование.
- **Минусы:** Огромные накладные расходы на поддержку инфраструктуры на этапе MVP, сложность локального запуска, замедление темпа разработки в 3-4 раза.

### Вариант 2: Монолит на Django
- **Плюсы:** Готовая админка, мощная ORM, развитая экосистема.
- **Минусы:** Избыточный вес для легковесного API/бота, сложнее интегрировать кастомные async event-loops.

### Вариант 3 (Выбранный): Модульный монолит на FastAPI + SQLite / SQLAlchemy
- **Плюсы:** Молниеносный запуск, строгая типизация через Pydantic v2, асинхронная архитектура из коробки, нулевые затраты на развертывание базы данных для MVP.
- **Минусы:** Ограничения SQLite при экстремальной параллельной записи (легко решается переходом на PostgreSQL без изменения кода бизнес-логики благодаря ORM).

---

## 3. Принятое решение
Принято решение строить систему как **модульный монолит на FastAPI** с абстракцией слоя доступа к данным через SQLAlchemy. В качестве первоначальной БД используется SQLite с последующей миграцией на PostgreSQL при росте нагрузки.

---

## 4. Последствия
- **Позитивные:** Проект запускается одной командой без поднятия фоновых контейнеров БД; полная автогенерация документации Swagger OpenAPI.
- **Негативные / Риски:** При масштабировании на несколько серверов потребуется переход на внешний сервер БД.
- **План смягчения:** Все обращения к БД изолированы в репозиториях (`src/repositories/`), что позволит сменить диалект БД за 5 минут простой правкой connection string.
