# 🐛 BUG-000: Ошибка занятости сетевого сокета порта при повторном перезапуске (Эталонный пример)

- **Дата обнаружения:** 2026-09-18
- **Статус:** 🟢 РЕШЕНО
- **Затронутый компонент:** Запуск dev-сервера (Uvicorn / Node.js)
- **Обнаружил агент:** Gemini 3.8 Flash

---

## 🔍 1. Симптом (Что произошло)
При попытке повторного запуска сервера на локальном порту 8000 процесс падает с критической ошибкой:

```text
ERROR:    [WinError 10048] Only one usage of each socket address (protocol/network address/port) is normally permitted
OSError: [Errno 48] Address already in use
```

---

## 🔬 2. Первопричина (Root Cause)
Предыдущий фоновый процесс сервера не был завершен корректно (зомби-процесс остался висеть в памяти после аварийного разрыва терминала или отмены команды), удерживая привязку к TCP-порту 8000.

---

## 🛠️ 3. Решение (Как исправлено)
1. Выполнен поиск PID процесса, удерживающего порт:
   ```powershell
   # Для Windows:
   Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue | Select-Object OwningProcess
   Stop-Process -Id <PID> -Force

   # Для Linux / macOS:
   lsof -ti:8000 | xargs kill -9
   ```
2. В скрипт запуска добавлен предварительный хук очистки порта перед стартом.

---

## 🛡️ 4. Правило предотвращения (Prevention Rule)
- Перед запуском dev-сервера на фиксированном порту всегда проверять, свободен ли сокет.
- В фоновых командах запуска указывать корректный таймаут и обработчик SIGINT / SIGTERM.
