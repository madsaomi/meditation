# 📐 Каталог планов реализации (Implementation Plans)

> [!IMPORTANT]
> **ПРАВИЛО PLAN-FIRST (СНАЧАЛА ПЛАН — ПОТОМ КОД):**  
> Прежде чем писать или изменять хоть одну строчку кода, агент **ОБЯЗАН** составить детальный план реализации и зафиксировать его. Написание кода без предварительного плана категорически запрещено!

---

## 🎯 Назначение папки
В эту папку (`agents/plans/`) сохраняются детальные проектные спецификации и пошаговые планы реализации фич, рефакторингов, интеграций и архитектурных изменений.

Формат именования файлов:  
`plan_<номер>_<краткое_название>.md` (например: `plan_001_auth_system.md`, `plan_002_database_migration.md`).

---

## 🚀 Регламент создания и утверждения плана:
1. **Создание плана:** Скопировать шаблон [`agents/templates/template_plan.md`](file:///agents/templates/template_plan.md) в `agents/plans/plan_XXX_<name>.md`.
2. **Заполнение разделов:**
   - Четко сформулировать цель и ожидаемый результат.
   - Провести инспекцию кодовой базы и составить точный перечень затронутых файлов (`[NEW]`, `[MODIFY]`, `[DELETE]`).
   - Декомпозировать реализацию на атомарные, проверяемые шаги с чек-боксами `[ ]`.
   - Зафиксировать возможные риски и стратегию отката (Rollback plan).
   - Определить критерии приемки и тестовые команды.
3. **Утверждение (Approval Gate):**
   - Если работа ведется в интерактивном режиме с пользователем — представить план и дождаться подтверждения.
4. **Реализация строго по плану:**
   - Писать код только в соответствии с утвержденными шагами.
   - Параллельно отмечать выполненные пункты `[x]`.
   - При обнаружении непредвиденных архитектурных препятствий — обновить план *до* внесения спонтанных правок в код.
5. **Завершение:** После завершения всех шагов и успешного тестирования сменить статус плана на `✅ COMPLETED`.
